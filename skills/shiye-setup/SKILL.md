# 拾页 · 引导

你要把用户带到一个状态：在他的工作目录里跑 `doctor` 全部通过。之后做书用另一个 skill（`skills/shiye/SKILL.md`）。

下文的 `<skill>` 是这个仓库的根目录（本文件往上两级）。命令都在用户的工作目录里跑。

## 步骤

1. **定工作目录。** 问用户想把笔记和成品放在哪个文件夹，没想法就用当前目录下的 `拾页/`。进到那里跑 `python3 <skill>/run.py init`，它会建 `inbox/`、`books/`、`issues/` 和一份空的 `.env`。
2. **装引擎。** `pip install -r <skill>/requirements.txt`，`bash <skill>/scripts/fetch-fonts.sh`。装不上就把报错原样告诉用户，不要绕过去。
3. **问笔记在哪。** 只问这一个问题：「你平时把想读的东西收藏在哪？」然后对照 `<skill>/adapters/*/adapter.json`（`kind` 是 `notes` 的）：
   - 用户说的地方有对应的连接器：读它的 `ask`，一项一项问。每一项把 `how`（去哪拿）一起告诉用户。有 `costs`（要花钱）或 `account_changes`（会动他的账号）的，问之前先说清楚，用户不愿意就不接。
   - 没有对应的连接器：请用户把笔记导出成文件（文本、Markdown、截图、链接清单都行），放进 `inbox/`。这样也完全能做。
4. **问书。** 告诉用户书有两个来路：他自己的电子书放进 `books/`；或者接书库（`adapters/books-mcp/`）。他有书库的地址和 key 就按那个目录的 `README.md` 接上，然后你自己调一次 `search_books` 搜一本书确认能用。没有就跳过，做书时拿不到的书会列出来请他补。
5. **把答案写进 `.env`。** 用户给的每个值写到工作目录的 `.env` 对应的那一行。不要把凭证写进别的文件，不要在回复里复述凭证，不要提交。
6. **自检。** `python3 <skill>/run.py doctor`。有 ✗ 的逐条解决：凭证填了但连不上，把它打印的原因告诉用户，请他核对后重填。直到退出码是 0。
7. **收尾。** 用两三句话告诉用户：接上了什么，没接什么，接下来说一句「做一期」就可以开始。

## 规矩

- 一次只问一件事，问的时候说明为什么要、去哪拿。
- 用户不想给的就不接，不追问。只要 `inbox/` 里有东西或者接上了一个笔记来源，就算装好。
- 凭证只进 `.env`。任何输出、日志、回复里都不出现凭证的值。
- 以后要换来源或加来源，重新走第 3 步到第 6 步。
